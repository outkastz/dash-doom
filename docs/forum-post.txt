[h]Getting DOOM to run on a Sony Dash[/h]

Sony Dash HID-C10, a.k.a. a Chumby with a Sigma Designs set-top-box chip inside. Got id Software's [i]DOOM[/i] running natively on it - full source, write-up, and a ready-to-copy USB kit are all up on GitHub now:

[url]https://github.com/outkastz/dash-doom[/url]

[b]Status:[/b]
[list]
[*][color=green]Video: PROVEN[/color] - DOOM fully playable, ~40fps, correct color[/*]
[*][color=red]Audio: BLOCKED[/color] - digital pipeline 100% solved, silent at the speaker[/*]
[*][color=orange]Signed normal boot: OPEN PROBLEM[/color][/*]
[/list]

Device: Sony Dash HID-C10 - SoC: Sigma Designs SMP8654 ("tango3") - CPU: MIPS32LE, kernel 2.6.22.19

Nothing here required opening the case or touching a chip with a probe. Every result came from software running on the device itself, over the network, through the official recovery-flash mechanism.

[b]The short version:[/b]
[list]
[*]The recovery menu's Flash player preloads a widget off USB - that's the code-execution foothold the whole thing runs on.[/*]
[*][code]/dev/fb0[/code] is a dead end on this hardware - the real display path is Sigma's undocumented [code]librua[/code]/[code]libdcc[/code] "RM/DCC" API, reverse-engineered enough to get double-buffered, correctly-colored frames on the panel.[/*]
[*]DOOM ([code]doomgeneric[/code]) runs on top of that at ~40fps, cross-compiled for the Dash's ancient MIPS/glibc.[/*]
[*]Audio's digital pipeline is fully solved and verified (webcam-mic + FFT tone detection, no ears required) - it's blocked at the very last step, routing decoded PCM out to the physical speaker, because the recovery kernel has no sound core at all. Full trace of exactly where it dies is in the write-up.[/*]
[*]Also mapped out how the firmware actually protects itself (spoiler: the firmware images themselves aren't signed, just MD5-checked) - and found one open discrepancy between what the boot scripts say should work and what real hardware does. Details in the repo.[/*]
[/list]

[b]Want to try it yourself?[/b] The [code]usb-kit/[/code] folder in the repo is self-contained - copy it to a FAT32 stick, boot into Special Options, DOOM launches in ~10-15 seconds. No PC or network needed.

[b]Where we could use help[/b] (both are documented in detail in the repo, not just vague asks):
[list]
[*]Getting audio output routed without a kernel sound core - need the exact property sequence the ALSA driver sets up before the routing call that currently just hangs.[/*]
[*]Why a rootfs modification that should be harmless per the boot scripts actually loops the boot on real hardware, twice, two different ways.[/*]
[/list]
